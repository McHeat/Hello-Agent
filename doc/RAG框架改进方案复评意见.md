## 五、复评新发现的问题 —— 2 个 minor，不阻断开工

### 5.1 G2 量化验收与 Golden Set 扩充存在时序张力

3.1.1 的 G2 验收明确要求「在**扩至 30~50 条**的中文 Golden Set 上」验证，且注明当前 8 条样例 recall 已饱和不参与比较；但 Golden Set 扩充在第十一章属于**后续路线**（暂行阈值上线后、首次质量复盘时）。而 9.4 步骤 3 又写「跑**同一份** Golden Set……验证 3.1.1 的 G2 量化目标」——用初期规模（8 正 + 3~5 负）无法真正验证为 30~50 条设定的量化目标。

**建议修正**：在 9.4 步骤 3 与 9.3 的 G2 验收项加注「初版对照用现有样本记录数据，G2 正式量化验收随 Q6 扩充复标后完成」，消除内部矛盾。这正是 v2 把验收标准提高后带出的连锁时序问题，属表述级，实施时按加注执行即可。

### 5.2 「改造前」基准数据的采集顺序未规定

G3 的验收（10 万子块：改造前 3000+ 次写 vs 改造后 1 次）需要旧代码路径的数据，但方案未规定「阶段 3 动代码前先跑一次改造前基准」。若顺序颠倒，事后只能靠 git 检出旧版补测。

**建议**：在阶段 3 前置中加入「动代码前先采集 10 万子块基准（写次数 + 耗时）」一步。
